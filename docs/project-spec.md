# SPA BOOKING — спецификация проекта

## 1. Пользователь и проблема

**Пользователь:** клиент массажного салона и администратор салона.

**Проблема:** запись ведётся вручную по телефону и в мессенджерах, из-за чего возникают накладки, теряются записи и клиенты. Клиенту неудобно уточнять свободное время, а администратору сложно держать расписание в голове.

**Решение:** единое приложение, где клиент сам выбирает услугу, мастера и время, а администратор видит все записи и управляет их статусами.

## 2. Основная сущность — Booking

| Поле | Тип | Пример | Назначение |
|---|---|---|---|
| id | string | bk-01 | Уникальный идентификатор |
| clientName | string | Анна Смирнова | Имя клиента |
| clientPhone | string | +7 900 123-45-67 | Телефон клиента |
| serviceTitle | string | Классический массаж | Название услуги |
| description | string | Общий массаж спины и шеи | Описание услуги |
| category | union | Массаж / SPA / Уход | Категория услуги |
| masterName | union | Ирина / Ольга / Дмитрий | Мастер |
| status | union | new / confirmed / done / cancelled | Статус записи |
| price | number | 3500 | Стоимость, ₽ |
| durationMin | number | 60 | Длительность, минут |
| date | string | 2026-09-05 | Дата визита |
| time | string | 14:30 | Время визита |
| isPaid | boolean | false | Признак оплаты |
| createdAt | string | 2026-08-30 | Дата создания записи |

## 3. Страницы приложения

| № | URL | Страница | Назначение |
|---|---|---|---|
| 1 | / | Дашборд | Сводка, ближайшие визиты, быстрые действия |
| 2 | /bookings | Все записи | Список, поиск, фильтры, сортировка |
| 3 | /bookings/:bookingId | Карточка записи | Подробная информация об одной записи |
| 4 | /bookings/new | Создание записи | Форма записи с валидацией |
| 5 | /analytics | Аналитика | Распределение по услугам и мастерам, выручка |
| 6 | /schedule | Расписание мастера | Занятые и свободные слоты |

Дополнительно планируется `/bookings/:bookingId/edit` — редактирование записи.

## 4. Пользовательские сценарии

1. **Создание записи.** Клиент выбирает услугу, мастера, дату и время, вводит имя и телефон. Запись появляется в списке со статусом «Новая».
2. **Просмотр своих записей.** Клиент фильтрует записи по статусу и открывает карточку.
3. **Подтверждение записи.** Администратор проверяет новую запись и подтверждает её.
4. **Отмена записи.** Запись переводится в статус «Отменена», слот освобождается.
5. **Просмотр расписания мастера.** Администратор выбирает мастера и дату, видит занятые и свободные слоты.
6. **Редактирование записи.** Меняются дата, время, мастер или услуга.

## 5. Действия над сущностью

- создать запись;
- открыть подробности;
- изменить запись;
- подтвердить;
- отменить;
- отметить завершённой;
- отметить оплату;
- найти, отфильтровать, отсортировать;
- посмотреть расписание мастера;
- использовать данные для аналитики.

## 6. Границы первой версии

**Входит:** запуск приложения, типизированная модель, mock-данные, стартовый экран, отображение записей и статусов, адаптивная вёрстка, README и спецификация.

**Не входит:** backend, база данных, Redux Toolkit, CRUD, React Router, localStorage, авторизация, онлайн-оплата, SMS и push-уведомления, внешние API.
